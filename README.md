# Постобработка OCR паспорта РФ

Решение принимает результаты OCR и возвращает решение по каждому документу:
`accept` с десятью полями или `reject`. Проверяются согласованность визуальной
и машиночитаемой зон, полнота полей и срок действия паспорта на **01.10.2026**.
Алгоритм детерминирован и работает на CPU без интернета.

## Запуск

Python 3.10 или новее; сторонние библиотеки не требуются. Проверено на Python 3.12.
Поместите исходный файл задания в `data/test_predictions.jsonl` и выполните
из корня проекта:

```sh
python postprocess.py data/test_predictions.jsonl answers.jsonl
```

Для каждой входной строки создаётся одна выходная строка с тем же `doc_id`.
У принятого документа присутствуют все десять полей в формате разметки;
у отклонённого ключ `fields` отсутствует. Итоговые предсказания для всех
2000 test-документов записаны в [answers.jsonl](answers.jsonl).

Рядом с программой должны находиться `model.json`, `policy.json`
и `reference/subdivisions.csv`. При запуске разметка и обучающие данные
не используются. Для сохранения причин отказов доступен журнал:

```sh
python postprocess.py data/test_predictions.jsonl answers.jsonl --audit validation/test_audit.jsonl
```

## Результаты

- **Test:** 517 принято из 2000 (**25,85%**), 1483 отклонено.
- **Train, итоговая модель:** 630 принято из 3000, 5 несовпадений с разметкой.
- **Групповая CV, 5 фолдов и 3 повтора:** 595 / 594 / 594 принято;
  в каждом повторе 5 несовпадений, точность среди принятых около **99,16%**.
- **Прогноз для test:** около **6 ошибок среди 517 принятых**;
  математическое ожидание 6,16, условный 95%-й предиктивный интервал 0-13.

Разметка test недоступна, поэтому фактическое число ошибок неизвестно.
Целевой нулевой уровень ошибок на локальной проверке не достигнут.
Подробности метода, анализа ошибок и прогноза:
[отчёт, 2 страницы](output/pdf/report.pdf), [текстовая версия](REPORT.md).

## Метод

1. **Сборка и полнота полей.** Строки визуальной зоны упорядочиваются по
   координатам; рамки и межстрочные разрывы проверяются на пропуски.
   Нормализуются даты, серия и номер, код подразделения и буквенные омографы.
2. **Сверка с MRZ.** Проверяются структура и контрольные цифры нижней строки,
   ФИО сопоставляются с визуальной зоной. Символы-заполнители `<` исключены
   из оценки уверенности верхней строки. Исправления допускаются при
   подтверждении другой зоной; уверенное противоречие приводит к отказу.
3. **Текстовые поля.** Орган выдачи сопоставляется с кодом подразделения
   и справочником DaData, дополненным названиями из train. Исправляется только
   близкий однозначный вариант. Место рождения не достраивается; незнакомое
   имя само по себе не является причиной отказа.
4. **Даты.** Проверяются календарная корректность, выдача после достижения
   14 лет, отсутствие будущей выдачи и замена в 20/45 лет с учётом 90 дней.
   Рождение до 1900 года и выдача до 01.10.1997 консервативно отклоняются.
   Для родившихся 29 февраля возрастная граница в невисокосном году приходится
   на 1 марта.

Пороги уверенности для `web`, `mobile` и `mobile_v2` заданы в `policy.json`.
Проверки реестров МВД не выполняются: сведения об утрате, аннулировании
и других основаниях недействительности во входных данных отсутствуют.

## Анализ пяти расхождений

Во всех повторах CV несовпадения относятся к одним и тем же документам.
Ниже указаны результат алгоритма и значение разметки соответственно:

- `tr_01506`, имя: КАБЛЯХБАР / КАБЛЯЖБАР;
- `tr_01665`, место рождения: ДЖАМБИЧИ / ДЖАМБИУИ;
- `tr_01765`, имя: ХАСАНЗЯН / ХАОАНЗЯН;
- `tr_02287`, фамилия: МУТЯНСКИЙ / МУТЯНСЖИЙ;
- `tr_02818`, имя: ЕВГЕНИЙ / ЕВТЕНИЙ.

Скорее всего, эти пять расхождений связаны с опечатками в разметке.
В четырёх случаях с ФИО визуальная зона и MRZ совпадают с высокой уверенностью.
Место рождения в MRZ отсутствует. Без исходных фотографий подтвердить гипотезу
нельзя, поэтому **все пять случаев учтены как ошибки**. Исключений по `doc_id`
и подстановок значений под разметку в алгоритме нет.

## Воспроизведение оценки

Поместите исходные `train_predictions.jsonl` и `train_labels.jsonl` в `data/`.

```sh
python fit_model.py
python run_cv.py --folds 5 --repeats 3
python forecast.py
python -m unittest discover -s . -p "test_*.py"
python check_delivery.py
```

Словари при CV обучаются только на обучающей части каждого фолда. Повторные
снимки одного паспорта объединены в группу; источники сбалансированы между
фолдами. В каждом повторе каждый документ получает одно предсказание
вне обучающей части. Итоговые словари обучены на всём train.

CV проверяет фиксированную политику, без вложенного подбора порогов.
Правила и пороги разрабатывались на этом же наборе, поэтому оценка может быть
оптимистичной. Повторы используют те же документы и не считаются независимыми
выборками. Прогноз использует повтор 0: Beta-биномиальная модель с априорным
распределением Джеффриса Beta(0,5; 0,5) отдельно для каждого источника.

Метрики, параметры разбиения и контрольные суммы кода и данных сохранены
в [validation/cv_final/](validation/cv_final/). При изменении протокола
задайте новую папку `--output` или явно передайте `--overwrite`.

Сверка предсказаний CV исходным оценщиком:

```sh
python evaluate.py validation/cv_final/grouped_cv/repeat-0/answers.jsonl validation/cv_final/grouped_cv/repeat-0/labels.jsonl
```

Проверка итоговой модели на train с дополнительным контролем дат:

```sh
python postprocess.py data/train_predictions.jsonl train_answers.jsonl
python validate.py train_answers.jsonl data/train_labels.jsonl --output validation/train_metrics.json
```

`evaluate.py` сравнивает поля без учёта регистра и повторных пробелов;
пунктуация учитывается. Он не проверяет действительность паспорта.
`check_delivery.py` проверяет формат test-ответов и их точное воспроизведение
в отдельной папке без обучающих файлов, сторонних пакетов и доступа к сети.

## Структура проекта

- `postprocess.py`, `model.json`, `policy.json`, `reference/` - алгоритм и ресурсы;
- `answers.jsonl` - предсказания для test;
- `output/pdf/report.pdf`, `REPORT.md` - отчёт;
- `fit_model.py`, `run_cv.py`, `cv_tools.py` - обучение и групповая CV;
- `evaluate.py`, `validate.py`, `forecast.py` - оценка и прогноз;
- `test_postprocess.py`, `test_cv.py`, `check_delivery.py` - проверки;
- `validation/` - сохранённые метрики и протоколы;
- `THIRD_PARTY_NOTICES.md`, `reference/SOURCE.txt` - источники и лицензия справочника.

Исходные OCR-данные и разметка доступны в архиве задания. Файлы предсказаний
и разметки фолдов создаются при запуске CV. Для пересборки PDF командой
`python build_report.py` отдельно требуются ReportLab и шрифт Arial или DejaVu Sans.
`python package_solution.py` собирает архив проекта и проверяет контрольные суммы.
